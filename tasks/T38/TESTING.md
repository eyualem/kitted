- *Test writer's notes on the set-up (what the tests actually do; the expectations above and below are unchanged):*
  - The render mocks and helpers live in one test-only module, `app/src/testing/t38ScreenMocks.tsx` (never imported by the app), shared by three render files: `drawnWelcomeScreens.test.tsx` (the bundled s14 example), `drawnWelcomeNoExample.test.tsx` (the engine-null case: `demoReadingById('s14')` returns null for that file only, so `welcomeExample()` and `exampleCheck()` are null however and whenever the screens read them) and `drawnWelcomeOtherReading.test.tsx` (the "nothing typed in" case, below).
  - **The mocked-example case is done one level down.** Swapping `welcomeExample`'s return for one test can't be done safely: the screen may read it at module load, and a fresh module registry (`jest.isolateModules`) reuses the mocks already loaded in the main one, giving two copies of React. So `drawnWelcomeOtherReading.test.tsx` swaps the bundled reading itself for another bundled reading, s05, for that file only. The real engine then gives other numbers (6.5 "Getting there" → 7.0 "Put together", fix "Swap the jeans for dark straight jeans", the bottoms swapped, no outer layer); the test computes them from the engine and both screens must show exactly those and none of s14's ("7.5", "8.0", "Sharp", the sneaker fix). This is at least as strict as the `{ score: 6, … 'Tuck the tee' }` mock: the swapped piece is a different slot (`drawn-piece-bottom-after`), so a build that hard-codes the shoes, the numbers or the words fails.
  - The clock: modern fake timers for `setTimeout`/`setInterval`/`Date`, with React's microtasks left real (so `jest.getTimerCount()` counts only the screen's own timers; with them faked, React's own queued microtasks counted as timers). `requestAnimationFrame` is a 16 ms frame on the fake clock (React Native's Jest preset defines it as a 0 ms timeout after the fake clock is built, so Jest can't fake it), and `performance.now()` reads the fake clock. Because a frame lands every 16 ms, the render tests read the mid-swap frame at t = 1150 (not 1100) and the end at t = 2050 (not 2000), and with the slow factor at 11 500 and 20 500; the pure timeline tests use the exact times.
  - Queries include VoiceOver-hidden elements (`defaultIncludeHiddenElements: true`; the drawing is hidden), and hiding is checked explicitly with `isHiddenFromAccessibility`. The card's parts (`welcome-card-*`) are looked up inside `welcome-card`, and the pieces (`drawn-piece-*`) inside `welcome-drawing` or `example-bubble`, so an invisible measuring copy can't be mistaken for what he sees.
  - `GarmentArt` renders a marker `View` (testID `garment-art`) carrying its `spec`, so the tests read what is drawn at that moment and inside which piece wrapper. `useFocusEffect` runs its callback like a real focus (so the old forced status bar is seen). Store writes are watched by wrapping every write method of the memory store and listening on the change bus. `expo-status-bar`'s `StatusBar`, if rendered, may only have no style or `auto`.
